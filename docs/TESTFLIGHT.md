# TestFlight — shipping OpenCircuit to external testers

> For the full App Store submission (privacy label, review notes, screenshots), see
> `docs/APP_STORE_SUBMISSION.md`.

Path from source → TestFlight. The dev-signed install (`devicectl`) is a *different* flow; this
one produces a **Release archive uploaded to App Store Connect (ASC)**.

## 0. Project state (already done in-repo)
- App icon: `ios/OpenCircuit/AppIcon.icon` (Icon Composer bundle; needs Xcode 26 to build).
- `ITSAppUsesNonExemptEncryption = false` — SM3 ring-auth hashing plus the Helio Strap's AES/ECDH
  link crypto, all ancillary to a health app (see `docs/APP_STORE_SUBMISSION.md`); skips the
  per-upload export-compliance prompt.
- `PrivacyInfo.xcprivacy` — no tracking, no off-device data collection (local-first), declares
  the one required-reason API (UserDefaults / CA92.1).
- Version/build wired to `MARKETING_VERSION` / `CURRENT_PROJECT_VERSION` in `project.yml`.
- Shared `OpenCircuit` scheme + `ExportOptions.plist` + `scripts/testflight.sh`.

> NOTE: `ios/OpenCircuit/Info.plist` is **generated by XcodeGen** from `project.yml`'s
> `info.properties`. Never hand-edit the plist — it is overwritten on every `xcodegen generate`.
> Change `project.yml` instead.

## 1. Account prerequisites (one-time, you — not scriptable)
1. **Paid Apple Developer Program** active.
2. **Accept the latest Program License Agreement** as the Account Holder in ASC → *Agreements*.
   A pending agreement blocks all uploads. (This was a known blocker after the bundle-id rebrand.)
3. **Create the app record**: ASC → *Apps* → **+** → New App. Bundle id
   `com.standardsoftwaresolutions.opencircuit`, platform iOS, primary language, SKU.
4. **App Store Connect API key**: ASC → *Users and Access* → *Integrations* → *App Store Connect
   API* → generate a key with **App Manager** role. Download the `.p8` **once**, note the **Key ID**
   and **Issuer ID**.

## 2. Build number
ASC rejects a build number it has already accepted. Before each upload, bump
`CURRENT_PROJECT_VERSION` in `project.yml` (1 → 2 → …). `MARKETING_VERSION` (e.g. `1.0`) is the
user-facing version and only changes for releases.

## 3. Archive + upload
```bash
export ASC_KEY_ID=XXXXXXXXXX
export ASC_ISSUER_ID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
export ASC_KEY_PATH="$HOME/.appstoreconnect/private_keys/AuthKey_XXXXXXXXXX.p8"
ios/scripts/testflight.sh
```
The build appears in ASC → *TestFlight* after processing (a few minutes).
(GUI alternative: open the project in Xcode → *Product ▸ Archive* → *Distribute App ▸ TestFlight*.)

## 4. External testing requirements (beyond internal)
Internal testing (≤100 ASC team members) is instant after processing. **External** testing adds:
- **Beta App Review** — a lighter review than full App Store, but it *is* a review. Required once
  per significant build.
- **Privacy policy URL** — public, required. Must cover HealthKit data handling.
- **Test information** — what to test, and a **sign-in / demo path**. OpenCircuit needs a
  physical RingConn Gen 2 to do anything useful → call this out in the test notes, and ideally
  provide a short demo video, or reviewers may be unable to exercise the app.
- **External group + public link or invited emails** in ASC → TestFlight.

## 5. Review notes to pre-empt rejections
- **HealthKit**: usage strings present; data is read/written only to the user's own HealthKit and
  never leaves the device. State this in review notes.
- **Background modes** (`location`, `bluetooth-central`, `processing`): justify `location` as
  workout-only (route + keep-alive for HR while locked) — matches `NSLocationWhenInUseUsageDescription`.
- **Privacy label** in ASC: "Data Not Collected" (consistent with `PrivacyInfo.xcprivacy`).
